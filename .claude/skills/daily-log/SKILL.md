# 每日简历向日志生成器

你的任务是帮我复盘今天的工作，并按照指定的模板生成一份高质量的开发日志。

## 执行步骤：

1. **上下文收集 (Context Gathering)**：
   - 请在后台静默运行 `git status` 和 `git log --since="midnight"` 来查看我今天修改了哪些文件。
   - 回顾我们今天在终端里的对话历史，特别是关于代码报错、重构讨论和工具选择的内容。
   
2. **读取模板 (Load Template)**：
   - 请读取同目录下的模板文件：`templates/daily-log-template.md`。

3. **智能填充与深度挖掘 (Drafting)**：
   - 根据收集到的上下文填充模板。
   - **【最核心要求】**：在填写 `💡 技术选型与架构演进 (Resume Goldmine)` 这一节时，**绝对不能敷衍**。如果你在今天的上下文中发现了任何关于技术决策的蛛丝马迹（比如引入了新库、修改了数据库结构、优化了 Prompt 或 RAG 流程），请尽你所能分析出背后的“动机 (Problem)”和“权衡 (Trade-offs)”。
   - 如果今天的修改纯粹是体力活（比如修改错别字、调 CSS），请在这一节写“今日主要为常规特性开发，无重大底层选型演进”。

4. **确认与提问 (Interactive Refinement)**：
   - 在生成最终 Markdown 日志之前，如果你觉得今天某个核心功能的“业务价值”或“决策依据”不够清晰，**请先主动向我提问**（例如：“我看到你今天把 xx 换成了 yy，能告诉我主要是为了解决什么性能瓶颈吗？”），等我补充完信息后，再输出完整的日志。

5. **保存日志文件**：
   - 将日志写入 `.doc/daily-log/YYYY-MM-DD.md`（如 `.doc/daily-log/2026-04-17.md`）。
   - 如果目录不存在，先创建 `.doc/daily-log/` 目录。
   - 使用 Write 工具保存文件。

6. **输出结果**：
   - 将最终的 Markdown 内容输出到终端供我预览。
   - 告知用户日志已保存至具体路径。
